# Build bundle

## Build output

```text
artifacts/
└── build/
    ├── build.json
    ├── spec.json
    ├── plan.json
    ├── explorer.json
    ├── packages/
    │   └── project/
    │       └── pump_analytics.py
    └── runtimes/
        └── python/
            └── requirements.txt
```

## Package and runtime manifest

Each direct subdirectory of `packages/` is a package, and each direct subdirectory
of `runtimes/` is a runtime. Their directory names are their IDs. In `build.json`,
`artifacts.packages` maps package IDs to directory paths (`path`) and optional
runtime IDs (`runtime`). Multiple packages can reference the same runtime.
`artifacts.runtimes` maps each runtime ID to its definition file.

```json
{
  "packages": {
    "project": {"path": "packages/project", "runtime": "python"}
  },
  "runtimes": {
    "python": "runtimes/python/requirements.txt"
  }
}
```

The builder validates these paths and references. Runtime assignments are
deployment metadata, not instructions to install packages or launch a worker.

## Packaged source code

`packages/project/` contains the contents of the configured Python source directory. Runs use
this bundled copy by default, so editing or removing the original source does
not change which project code the saved build runs. Generated bytecode and source
symlinks are not included. Built-in wheel packaging is not supported.

## Runtime requirements

The Python packager looks for `python/requirements.txt` under `[runtimes].path`
(default: `runtimes/` relative to the project root). It falls back to a
`requirements.txt` directly in that directory, then to one at the project
root. If no file exists, it uses `[project].dependencies` in
`pyproject.toml`, preserving environment markers for the target installer.
If none of these sources declares requirements, the bundle omits the runtime
definition and its assignment. Projects with dynamic dependencies or optional
extras can supply their own self-contained `requirements.txt`.

### Install dependencies

Install the file in the target environment with
`pip install -r artifacts/build/runtimes/python/requirements.txt`. A generated file is not a
lockfile. Supply pinned requirements for repeatable installs. The build does
not resolve, install, or embed dependencies.

## Source paths and overrides

`build.json` records the selected specification source and original Python
source path. If the bundle has no project source package, runs look for the
saved original source and then use the configured or default source directory.
`--src-path` and the Python run API can explicitly override that selection.
Original Python source paths under the project root are stored
relative to that root. Source directories outside the project remain absolute.

To run a copied bundle, place it under `artifacts/build/` in the target project
and supply the runtime configuration and inputs the plan uses. Bind data paths
through runtime configuration rather than locating project data relative to
the bundled Python files.
