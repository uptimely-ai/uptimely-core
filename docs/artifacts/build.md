# Build bundle

## Build output

```text
artifacts/
└── build/
    ├── build.json
    ├── spec.json
    ├── plan.json
    ├── explorer.json
    ├── packages/
    │   └── project/
    │       └── pump_analytics.py
    └── runtimes/
        └── python/
            └── pyproject.toml
```

## Package and runtime manifest

Each direct subdirectory of `packages/` is a package, and each direct subdirectory
of `runtimes/` is a runtime. Their directory names are their IDs. In `build.json`,
`artifacts.packages` maps package IDs to directory paths (`path`) and optional
runtime IDs (`runtime`). Multiple packages can reference the same runtime.
`artifacts.runtimes` maps each runtime ID to its definition file.

```json
{
  "packages": {
    "project": {"path": "packages/project", "runtime": "python"}
  },
  "runtimes": {
    "python": "runtimes/python/pyproject.toml"
  }
}
```

The builder validates these paths and references. Runtime assignments are
deployment metadata, not instructions to install packages or launch a worker.

## Packaged source code

`packages/project/` contains the contents of the configured Python source directory. Runs use
this bundled copy by default, so editing or removing the original source does
not change which project code the saved build runs. Generated bytecode and source
symlinks are not included. Built-in wheel packaging is not supported.

## Runtime requirements

The Python packager copies `python/pyproject.toml` from `[runtimes].path`
(default: `runtimes/` relative to the project root), or `pyproject.toml` directly
in that directory if present. An explicit runtime definition replaces the root
project's metadata rather than merging with it.

Without an explicit definition, the bundle takes only static
`[project].requires-python` and `[project].dependencies` from the root
`pyproject.toml`. Dependency markers are preserved. Build-system settings, tool
settings, and optional extras are not included. If neither field is present,
the bundle omits the Python runtime definition and its assignment.
The example sets `[runtimes].path = "."` to use its root `pyproject.toml`
without maintaining a separate runtime file.

Use the metadata to choose a compatible interpreter and install the listed
dependencies in the target environment. The generated `pyproject.toml` is
runtime metadata, not an installable project or a lockfile. The build does not
install dependencies. See [Python runtime preflight](../guides/runtime-validation.md#python-runtime-preflight)
for what the Engine checks before execution.

## Source paths and overrides

`build.json` records the selected specification source and original Python
source path. If the bundle has no project source package, runs look for the
saved original source and then use the configured or default source directory.
`--src-path` and the Python run API can explicitly override that selection.
Original Python source paths under the project root are stored
relative to that root. Source directories outside the project remain absolute.

To run a copied bundle, place it under `artifacts/build/` in the target project
and supply the runtime configuration and inputs the plan uses. With Uptimely
Core and the declared dependencies installed on the target, run
`uptimely run TARGET_PROJECT` without `--build`. The original source checkout
is not needed when the bundle contains the project code.

The target needs write access to `artifacts/` for the build lock and latest-run
artifacts, and to any configured output locations. Bind data paths through
runtime configuration rather than locating project data relative to the
bundled Python files.
