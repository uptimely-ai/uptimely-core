# Profile

A **profile** is an analytical blueprint for an entity. It is logical presentation of the entity. The profile's logical presentation can be compiled to physical execution plan and eventually materialized as a dataset.

A profile can be identified by these attributes:

- Grain: Dimension and resolution
- Scope: What subset to include

The profile has specified set of **features**, data are atomic pieces information describing profile's analytical nature.

Logical features are generated by computational operators, that physically materialize the results.

## Profile grain

Each profile has specified grain. For example **machine telemetry** profile has machine and timestamp resolution from machine and time dimensions.

## Profile scope

Additionally, profile has **scope**. It enables including only subset of observations from the chose grain. Two profiles might have same grain, but different scope.

For example, you might have **machine telemetry for red machines** and **machine telemetry for blue machines**. This enables calculating their individual set of features.

## Features

Features are computed (often numerical) attributes describing profile's analytical output. In physical execution they are analogical to columns in a dataframe.

In Uptimely framework features are globally unique across the profiles. In that sense, profile can be identified by its feature signature, but the real identity for profile comes from its grain and scope.

## Operator

Profile has a set of operators that result to one or more features.

Operator binds to a an execution function together with required argument values. While you might have only a handful of reusable functions, there is typically much more operators that bind to them.

Operator has always compute binding, whose function applies an operation to data.

When the operator is computing data from another profile, an additional merge operation is required to consolidate it with the target profile.
